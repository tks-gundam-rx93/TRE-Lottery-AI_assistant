# ロト7履歴CSVの出典と検証

- 対象: 第1回～第703回（2013-04-05～2026-11-13）
- 原本: ユーザー提供の `loto7.csv`（CP932、24項目の賞金・当せん口数情報を含むCSV）
- DBに取り込む項目: 抽せん回、抽せん日、本数字7個、ボーナス数字2個
- 正規化先: `data/loto7_history_001_703.csv`（UTF-8、11項目）
- 原本SHA-256: `51a8446cd8478509b55e5b605fdfd900095c3e7983b3d03bc646a3cc94223d00`
- 正規化CSV SHA-256: `ab1530b24af2c965a9908fe7a2862b87a23b01b79a2d7746e8c486a7da7a79db`
- 正規化前の回号は1～703の連続で重複なし。各回の本数字7個とボーナス数字2個は、いずれも1～37の異なる数字で、互いに重複しない。
- 全日付は正規化後、金曜日かつ回号とともに昇順。
- **第483回の抽せん日の1件だけ修正:** CSVは2022-08-13（土）だが、正しくは2022-08-12（金）。数字データは変更していない。
- 日付検証の根拠: [楽天銀行のロト7第483回結果](https://takarakuji.rakuten.co.jp/backnumber/loto7/202208/)
- 注記: ファイル全703回の数字はユーザー提供元の内容を構造検証したもので、すべての番号を外部の公式サイトと個別照合したわけではない。**サイト全件の公式照合を完了したという意味ではない。**
- 今回のバンドル履歴は **第703回まで**。次回以降は管理者用CSV取込で追加可能。
- 公開したのは抽せん事実を表す11項目のみで、賞金・口数などのその他の列はリポジトリに含めていない。
- 合成学習データとの混在は行わない。

## 取込と検証

Renderに `LOTTERY_BOOTSTRAP_CSV=1` を設定した場合、FastAPI起動時にバンドルされたCSVを読み取り、TiDB `tre_lottery.draw_results` へ不足回のみ一括登録する。

- データ不一致を検知した場合は**全件ロールバック**。既存回の上書きなし。
- すべての登録を1トランザクションで行う。
- 再起動しても過去の同じ回はスキップする（冪等）。
- 実行結果はRenderアプリケーションログに件数だけ記録し、接続資格情報・当せんファイル全体は出力しない。
- 公開API `GET /api/history/status` で第1回～第703回、703件、欠落0件を確認する。
