# HARO 方式1：GIF／静止画像による音声連動UI

## 目的

方式2（SVGの耳・目を個別制御）とは異なり、**承認された元GIFそのもの**を再生して、見た目の一致度を優先する比較用実装。
独立ブランチ `feat/haro-v1-gif-animated-20261120` で、既存の予測機能・MySQL・音声処理は共通。

## アセット

| ファイル | 実体 | 利用タイミング |
|---|---|---|
| `web/assets/haro-speaking.gif` | 元の8フレーム・507×378px・各180ms | 発話中と動作テスト |
| `web/assets/haro-idle.webp` | 元GIFの第1フレーム（閉耳、画像品質92） | 起動後の待機中・発話停止後 |

GIFは1.44秒で1周し、発話中はループ再生する。WebPは静止画で自動アニメーションしない。
音声は従来のWeb Speech APIを使い、GIFに音声データは含めない。
GIFは3体が同じ画面に含まれるため**1体ごとの耳・目の動きを独立して制御することはできない**。

## クラスと動作

`HaroGifPlaybackController` が表示状態を制御し、既存の `HaroSpeechController` から呼び出される。

| 状態 | 表示 | 処理 |
|---|---|---|
| 初回ページ | 「AIハロ起動」ボタン | 未起動 |
| IDLE | `haro-idle.webp` | 閉耳・暗い目 |
| SPEAKING | `haro-speaking.gif` | 8フレーム×180msを繰り返し |
| STOP | `haro-idle.webp` | GIFのsrcを外し、第1フレームに戻す |

### 再生を頭から開始する理由

HTML標準の `img` 要素にはGIFの再生位置を直接設定するAPIがない。
発話開始のたびに `?play=N` を付けた画像URLを設定し直し、GIF先頭フレームから再生する。
GIF読込完了まではWebPを表示する。読込失敗時はWebPへ戻す。

### 操作

1. 「AIハロ起動」を押すと初回のシステム音声と同時にGIFを再生
2. 緑／橙／紫のボタンで発話者の選択とログを切替
3. 発話中はGIF全体を再生し、音声終了で自動停止
4. 「耳・目の動作テスト」では約4.6秒のアニメを確認できる
5. 「音声停止」を押すとGIFも終了して待機へ復帰

## 既知の制約

- GIFの全3体が同時に開閉する。発話者に応じた1体だけの動作や、音声波形への厳密同期はできない
- GIFの描画解像度は507×378ピクセル。大画面では拡大によるボケが生じる場合がある
- PC/iPhoneともに表示は可能だが、マイク音声認識はHTTPS・ブラウザに依存
- ブラウザによってはキャッシュとGIF描画開始の扱いが異なり、再生開始前にわずかな待ち時間が発生する
- 画面を見て差が分かるよう、この分岐のGIF版は方式2のSVG版のデプロイURLと別にする
